  1. One key, fifty machines

    A license key gets pasted into a forum, a wiki, a CI file. LicenseForge counts activations per machine fingerprint and refuses the seat that goes over the plan's limit. Moving a seat is a support action, not a loophole.

  2. Customers behind an air gap

    Banks, defense, factories: their clusters never reach your server. Their app writes a request file; you answer with a signed license file bound to that machine. It expires on time and can't be copied to another host.

  3. Turning the clock back

    Every license file and lease carries signed server time. The SDKs' clock guard keeps the latest time it has trusted, so a machine set back a year doesn't get its trial back.

  4. Revoke, suspend, renew

    Online apps hold a lease of minutes or days, not a forever license. Suspend or revoke and the next refresh is refused. Renew and the same key keeps working: the machines pick up the new expiry by themselves.

  5. Replicas aren't customers

    A Deployment with six replicas shouldn't use six seats. Cluster-bound licenses fingerprint the cluster and share one lease through a ConfigMap or Secret, with RBAC limited to that one object.

How it works

Three steps from catalog to a checked feature.

1

Define

Products, features (on/off or limits like nodes) and plans with terms, seat limits, lease length and offline rules. One matrix decides what each plan includes.

2

Issue

From the dashboard, the API or the CLI; webhooks keep your CRM in step. Each license snapshots its plan, so later plan changes never surprise a customer.

3

Verify

Your app embeds your public keys and checks the signed file itself: product, machine, expiry, features. No network call on the hot path.

if status == licensefile.StatusGrace { warn("renew soon") }

import { open, parseKeySet, LicenseError } from "@licenseforge/sdk";

const keys = parseKeySet(readFileSync("./licenseforge-keys.json"));
try {
  const { claims, status } = open(licenseText, keys, { now: new Date(), product: "acme-db", fingerprint });
  if (status === "grace") warn("renew soon");
  if (!claims.entitlements.allows("nodes", nodes.length + 1)) refuse("node limit reached");
} catch (e) {
  if (e instanceof LicenseError) refuse(e.code); else throw e;
}
String text = Files.readString(Path.of("license.lic"));
try {
  LicenseFile.Opened lic = LicenseFile.open(text, keys,
      CheckOptions.of(Instant.now(), "acme-db").withFingerprint(fingerprint));
  if (lic.status() == LicenseFile.Status.GRACE) warn("renew soon");
  if (!lic.claims().entitlements().allows("nodes", nodes.size() + 1)) refuse("node limit reached");
} catch (LicenseException e) {
  refuse(e.code().spec());
}

Built for vendors who sell to serious customers

Everything around the license, too.

Signed, verifiable, specified

Ed25519 signatures over an open, versioned format with conformance vectors every SDK runs. Rotate signing keys without breaking shipped builds.

Kubernetes-native

Helm chart, hardened by default: non-root, read-only filesystem, NetworkPolicy, secrets as files.

Multi-tenant

PostgreSQL row-level security on every tenant table, OIDC login, per-tenant MFA policy, scoped API tokens.

Audit you can prove

A hash-chained audit log of every change and refusal, exportable to your SIEM.

Webhooks

License and activation events with Standard Webhooks signatures, delivered with retries and an SSRF guard.

Maintenance & renewals

Perpetual with updates-until, subscriptions renewed in place, grace periods, trials and site licenses.

Compliance from day one

FIPS 140-3 mode for the Go server and SDK, a NIST 800-53 control matrix in OSCAL, signed releases with SBOMs and SLSA provenance.
